## 1. 执行摘要

“微表情分析软件”这个方向有市场需求，但直接做“读心”“测谎”“真实情绪识别”不是好切口。更可行的产品定义是：**面向研究、UX、广告测试、医疗/交互辅助等场景的可解释面部行为分析工具**，输出 Action Units、头姿、眼动、面部质量、疑似短时表情事件、置信度和可复核时间线，而不是直接断言人的内心情绪或是否撒谎。

当前市场有三个明显断层：

1. 开源工具强在算法和研究复现，但弱在安装、可视化、人工复核、报告、团队协作和中文场景。
2. 商业软件强在工作流和多模态集成，但价格高、黑盒、云端隐私压力大，并且越来越避免“微表情测谎”叙事。
3. 云 API 多数只提供静态或低频的“表情/情绪属性”，不能覆盖真正的高帧率微表情 spotting、onset/apex/offset 标注和可审计证据链。

建议突破口：**做一个 privacy-first 的面部行为分析工作台 + SDK**。第一阶段聚焦“视频上传/本地分析 -> AU 与头姿时间线 -> 疑似微表情片段 -> 人工校正 -> 导出研究报告和结构化数据”。不要先做泛化的“情绪 AI”，而是把“可信、可复核、可合规”的行为数据做扎实。

## 2. 概念边界：不要把微表情等同于情绪或谎言

微表情通常指短暂、低幅度、局部的面部动作，常见说法是持续时间约 1/25 秒到 1/3 秒。真正识别这类信号通常需要高帧率视频、稳定光照、较高分辨率和严谨标注。普通 30fps 摄像头只能捕获很有限的短时动态，容易把眨眼、头动、压缩伪影、遮挡、说话口型误判成“微表情”。

更关键的是，科学上不能简单从脸部动作反推人的内心情绪。Barrett 等人在 2019 年的综述中指出，面部肌肉动作与情绪类别之间不存在足够稳定的一一对应关系。AWS Rekognition 的文档也明确提醒，其 `Emotion` 字段描述的是检测到的面部表情外观，而不是人的内在情绪状态。

因此，产品语言应该从：

- “识别真实情绪”
- “识别撒谎”
- “看穿心理”

转成：

- “检测面部行为事件”
- “量化 FACS / Action Units”
- “标注疑似短时表情变化”
- “提供可复核的视频证据和置信度”
- “辅助研究者/分析师缩短标注时间”

这不是保守，而是商业化的护城河：**可信度和合规性会成为竞争壁垒**。

## 3. 市场分层

### 3.1 开源与研究工具

| 工具/项目 | 主要能力 | 优势 | 短板 |
|---|---|---|---|
| OpenFace / OpenFace 3.0 | 人脸关键点、头姿、眼动、AU、表情识别流水线 | 学术影响力大，可做 baseline，输出结构化 | 部署门槛较高，UI 与产品化弱，微表情专项能力有限 |
| Py-Feat | Python 化的面部表情分析，支持检测、AU、情绪、可视化 | 对研究者友好，便于快速实验 | 更偏分析库，不是完整产品；性能和生产部署需补齐 |
| LibreFace | 实时面部表情分析工具包 | 面向实时和开源复现 | 生态与商业工作流弱 |
| MediaPipe Face Landmarker | 关键点、3D face mesh、blendshape、头姿相关能力 | 轻量、跨端、适合端侧原型 | 不是 FACS/微表情研究工具，需自建 AU/事件层 |
| 各类 MER GitHub 论文复现 | 微表情识别、spotting、跨库实验 | 可追踪 SOTA 思路 | 复现质量参差、数据集小、工程可用性弱 |

开源侧的机会不在“再造一个模型仓库”，而在把这些底座组合成可用产品：视频管理、质量检测、时间线、人工校正、导出、报告、权限、隐私。

### 3.2 商业研究软件与平台

| 产品/公司 | 主要定位 | 观察 |
|---|---|---|
| Noldus FaceReader | 学术/行为研究级面部表情分析软件 | 功能成熟，支持表情、AU、多脸、部分生理指标联动，适合实验室；价格和闭源是进入门槛 |
| iMotions | 多模态行为研究平台，集成人脸、眼动、EDA、EEG 等 | 工作流强，适合高校、企业研究和 UX lab；本质是平台型，而不是单点微表情工具 |
| Affectiva / Smart Eye | Emotion AI、车载、媒体分析、注意力等 | 商业重心更偏多模态、注意力和车载安全，不再只是“脸部情绪” |
| Realeyes / Adverteyes | 广告和媒体注意力、情绪反应测试 | 面向广告素材评估和注意力指标，强调商业洞察 |
| Entropik | 消费者研究、广告测试、UX 研究中的 facial coding / eye tracking | 同样是多模态研究平台方向 |
| Hume AI Expression Measurement | 表情测量 API/模型 | 其 Expression Measurement API 已公告在 2026-06-14 停用，说明单独“表情 API”路线存在产品战略压力 |

商业侧的共同趋势是：**从“识别情绪”转向“多模态人类反应测量”**。它们卖的不是单个模型，而是研究流程、面板样本、数据管理、报告和决策辅助。

### 3.3 云 API 与通用视觉服务

国内外云 API 通常提供“人脸属性/表情/情绪”字段，例如高兴、悲伤、愤怒、惊讶、中性等。这类 API 的优点是接入快，缺点也很明显：

- 多数针对静态图片或低频视频帧，不适合微表情的高帧率时序检测。
- 输出类别粗，通常没有 AU 强度、onset/apex/offset、帧级证据链。
- 合规压力大，尤其涉及人脸、生物识别、情绪推断、员工/学生监控时。
- 难以做本地私有化、离线分析、审计和人工校正。

这些 API 更适合作为参考竞品，不适合作为 FaceCat 的直接产品形态。

## 4. 技术与数据现状

### 4.1 典型技术流水线

一个严肃的微表情/面部行为分析系统至少包含：

1. 视频采集与质量评估：帧率、曝光、分辨率、脸部占比、遮挡、模糊、压缩伪影。
2. 人脸检测与跟踪：多人脸、跨帧 ID、丢帧恢复。
3. 关键点与头姿估计：2D/3D landmarks、yaw/pitch/roll。
4. 眼动与视线估计：gaze、眨眼、注视区域、眼睑运动。
5. AU / blendshape 提取：AU 强度、presence、左右不对称。
6. 时序事件检测：onset、apex、offset、持续时间、局部变化幅度。
7. 事件聚类与候选片段生成：把帧级变化转成可复核 clips。
8. 人工校正与标注一致性：多标注者、版本、置信度、导出。
9. 报告与审计：不只给结论，还要给证据、限制和模型卡。

真正的产品差异化往往出现在第 6 到第 9 步，而不是第 2 到第 5 步。

### 4.2 数据集与泛化问题

微表情研究常见数据集包括 SMIC、CASME II、SAMM、MMEW、CAS(ME)^2、CAS(ME)^3 等。它们对学术研究很重要，但用于商业泛化时有明显限制：

- 样本规模普遍小，受试者人数有限。
- 类别分布不均衡，不同数据集标签体系不完全一致。
- 数据通常来自实验诱发环境，和真实会议、课堂、访谈、广告观看场景差异大。
- 高帧率数据集和普通摄像头数据的域差异很大。
- 跨文化、跨年龄、肤色、光照、遮挡、眼镜、胡须、化妆等因素会影响结果。

这意味着不要过早承诺“通用准确率”。更好的说法是：FaceCat 提供**质量门控、置信度、场景校准和人工复核**，帮助用户在自己的数据上建立可追踪结论。

### 4.3 微表情模型的实际难点

| 难点 | 对产品的影响 |
|---|---|
| 持续时间短 | 需要高帧率或时序插值；普通 30fps 下只能做“短时面部变化候选” |
| 幅度小 | 需要稳定跟踪和光照归一化，质量不达标时必须提示不可分析 |
| 标签主观 | 需要人工复核、标注协议、标注者一致性指标 |
| 情绪标签不稳 | 输出应以 AU/行为事件为主，情绪只能作为弱推断或研究者自定义标签 |
| 跨域泛化差 | 需要场景配置、校准集、模型卡、数据版本管理 |
| 合规敏感 | 默认本地分析、最小化存储、明确用途边界 |

## 5. 合规与伦理风险

### 5.1 欧盟 AI Act 的直接影响

欧盟 AI Act 已经把“情绪识别系统”定义为基于生物识别数据识别或推断自然人情绪或意图的 AI 系统。其禁止项中特别限制工作场所和教育机构中的情绪识别系统，医疗或安全目的有例外但需要严格论证。

这对产品定位非常关键：

- 不要把产品卖给 HR 用于招聘、绩效、员工情绪监控。
- 不要卖给学校做学生注意力/情绪评分。
- 不要做“风险人员识别”“撒谎检测”“服从度判断”。
- 如果做医疗、康复、心理研究、驾驶安全等场景，要保留人工决策和明确限制。

### 5.2 中国与美国市场

中国市场涉及个人信息保护法下的敏感个人信息、人脸识别、图像采集告知同意、数据最小化、目的限定和跨境传输等问题。美国市场则需关注州级生物识别法，例如 Illinois BIPA，以及雇佣、教育、保险、医疗等场景的额外限制。

产品层面应该默认：

- 本地优先，不上传原始人脸视频。
- 支持原始视频不出设备，只导出匿名化时间序列。
- 明确告知采集目的、处理方式、保存期限和删除机制。
- 不做人脸身份识别，不做身份库比对。
- 不给个人做不可解释的自动化惩罚或评价。

### 5.3 产品红线

FaceCat 应明确拒绝或不优先支持：

- 招聘/绩效中的情绪评分。
- 学生课堂情绪/注意力打分。
- 微表情测谎和审讯结论生成。
- “犯罪倾向”“心理状态异常”自动判断。
- 在未告知或无同意情况下做隐蔽分析。

## 6. 可行机会点

### 机会 A：研究级 AU/微表情标注工作台

目标用户：高校实验室、心理学/传播学/行为科学研究者、用户研究团队、广告测试团队。

核心价值：

- 把 OpenFace/Py-Feat/MediaPipe 等底层能力做成低门槛工具。
- 自动生成 AU、头姿、眼动、质量指标的时间线。
- 自动标出疑似短时表情事件，供人工复核。
- 提供 onset/apex/offset 标注、片段回放、慢放、逐帧查看。
- 导出 CSV、JSON、ELAN、BORIS、Praat 或自定义格式。
- 生成研究报告：方法、参数、数据质量、候选事件、限制说明。

为什么可做：

- 需求真实，研究者愿意为节省标注时间付费。
- 不需要一开始证明“情绪识别通用准确率”。
- 可以开源模型 + 自研工作流，开发风险较低。
- 中文文档、中文报告和本地化部署是差异化。

### 机会 B：隐私优先的本地 SDK

目标用户：医疗辅助、康复训练、车载、机器人、人机交互、企业内测、线下实验室。

产品形态：

- 桌面端 SDK：Windows/macOS/Linux。
- Web SDK：浏览器 WebGPU/WASM，适合在线 UX 测试。
- 移动端 SDK：iOS/Android 端侧提取 landmarks/blendshape/AU。

核心差异：

- 原始视频不上传。
- 可关闭身份识别，只输出匿名化行为特征。
- 可以配置只保留统计结果，不保留图像。
- 提供模型卡、质量门控和日志审计。

### 机会 C：广告/UX 的注意力与反应分析

目标用户：品牌方、广告代理、短视频团队、电商内容团队、产品 UX 团队。

产品语言不要叫“微表情识别”，而叫：

- 内容注意力曲线
- 观看反应峰值
- 困惑/流失风险片段
- 正负反应候选点
- 用户测试 highlight reel

这个方向的商业价值更直接，但竞争也更强，需要结合样本招募、远程测试、报告模板和团队协作。

### 机会 D：微表情数据集与评测服务

目标用户：高校、算法团队、企业研究院。

可以做：

- 中文/亚洲人群、多光照、多设备、多场景数据采集工具。
- 标注协议和多标注者一致性管理。
- 跨库评测 benchmark。
- 模型卡和偏差评估报告。
- 以服务或平台方式提供私有评测。

这个方向壁垒最高，但启动慢，适合和高校或实验室合作。

## 7. 推荐切入点

优先级排序：

1. **研究级 AU/微表情标注工作台**
2. **本地隐私 SDK**
3. **广告/UX 反应分析报告**
4. **数据集与评测服务**

不建议先做：

- 通用情绪识别 SaaS API。
- 面试/招聘/教育监控。
- 测谎或安全审讯工具。
- 只卖一个模型接口但没有可视化和复核工作流。

最好的第一版定位：

> FaceCat 是一个本地优先的面部行为分析工作台，帮助研究者和产品团队从视频中提取 AU、头姿、眼动、短时表情事件和可复核证据，减少人工标注时间，并生成合规可审计的分析报告。

## 8. MVP 方案

### 8.1 MVP 用户流程

1. 用户导入视频或摄像头录制数据。
2. 系统检测视频质量：帧率、脸部大小、遮挡、光照、模糊、多人脸。
3. 系统逐帧提取 landmarks、head pose、gaze、AU/blendshape。
4. 系统根据时序变化生成疑似短时表情事件候选。
5. 用户在时间线上查看候选事件，逐帧校正 onset/apex/offset。
6. 用户给事件打标签，例如 AU12、AU4、AU1+2、smile、brow lowerer、uncertain。
7. 系统导出 CSV/JSON 和可读报告。

### 8.2 MVP 功能清单

必做：

- 视频导入、逐帧预览、慢放、时间线缩放。
- 人脸质量评分和不可分析提示。
- 头姿、关键点、AU/blendshape 时间序列。
- 疑似短时事件检测。
- 人工标注与修正。
- 片段导出、CSV/JSON 导出。
- 报告模板：方法、参数、质量、候选事件、限制说明。

可选：

- 多标注者一致性。
- ELAN/BORIS 导出。
- 批量处理。
- 项目管理和团队权限。
- WebGPU 本地推理。
- 多模态同步：音频、眼动仪、EDA、问卷。

暂缓：

- 直接情绪评分。
- 真假/欺骗判断。
- 在线大规模人脸分析 API。
- HR/教育监控模板。

### 8.3 技术架构建议

第一阶段可以组合成熟组件：

- 人脸检测/关键点：MediaPipe、OpenFace、RetinaFace/InsightFace 类模型。
- AU baseline：OpenFace、Py-Feat、LibreFace。
- 时序事件：滑动窗口、变化点检测、光流/landmark displacement、AU 强度突变、TCN/Transformer baseline。
- 可视化：Web 前端 timeline + video canvas，或桌面端 Electron/Tauri。
- 数据格式：项目文件 + parquet/csv/json，保留可复算参数。

核心原则：

- 先做“分析证据链”，后做“结论标签”。
- 每个事件都能回放到原视频帧。
- 每个输出都带置信度和质量上下文。
- 低质量视频明确标记为不可分析或低可信。

## 9. 评估指标

算法指标：

- Spotting F1 / Precision / Recall。
- Onset/apex/offset 时间误差。
- AU presence F1 和 intensity ICC/MAE。
- 跨数据集泛化性能。
- 普通摄像头 vs 高帧率摄像头的性能差异。

产品指标：

- 人工标注时间减少比例。
- 标注者一致性提升。
- 单小时视频处理时间。
- 质量门控召回率。
- 报告被研究者采纳比例。
- 导出格式兼容性。

商业指标：

- 单实验室/团队年费。
- 私有化部署客单价。
- SDK 集成转化率。
- 咨询/评测服务收入。

## 10. 商业模式建议

### 10.1 研究工具订阅

适合高校、实验室、UX team。

- Free：小视频、基础导出、水印报告。
- Pro：批量处理、完整导出、报告模板。
- Team：多项目、多标注者、权限、审计。
- Enterprise：私有化、本地模型、定制格式、合规支持。

### 10.2 SDK 授权

适合医疗、车载、机器人、教育科研设备商。

- 按设备数授权。
- 按项目授权。
- 私有化部署和离线授权。
- 提供模型卡和集成支持。

### 10.3 数据与评测服务

适合算法团队和研究机构。

- 自有数据清洗和标注。
- 模型 cross-dataset 评测。
- 偏差和公平性报告。
- 论文/实验复现实验环境。

## 11. 竞争策略

FaceCat 不应和 Noldus/iMotions 在第一天就正面对打全平台，而应切开一个更窄但更锋利的口子：

| 维度 | 大厂/成熟商业软件 | FaceCat 可以主打 |
|---|---|---|
| 部署 | 多为商业闭源/报价制 | 本地优先、轻量、可私有化 |
| 可解释性 | 有报告，但算法黑盒 | 开源 baseline + 可复核证据链 |
| 中文场景 | 支持有限 | 中文 UI、中文报告、中文数据协议 |
| 微表情专项 | 多数偏宏表情/情绪 | 重点做短时事件 spotting 和标注 |
| 成本 | 高 | 研究者/小团队可承受 |
| 合规 | 平台规则固定 | 默认隐私最小化，场景红线明确 |

## 12. 主要风险

1. 科学风险：用户可能期待“识别真实情绪”，但产品只能可靠提供行为事件。
2. 数据风险：缺少高质量自有数据时，模型泛化有限。
3. 合规风险：情绪识别在人事、教育、监控等场景容易触线。
4. 竞争风险：成熟平台功能全面，云厂商接入便宜。
5. 产品风险：如果只做算法 demo，用户不愿付费；必须做完整工作流。

应对方式：

- 产品文案坚持“行为分析/辅助标注”，不承诺读心。
- 每个分析结果附带质量、置信度和可复核帧。
- 先服务研究者，和用户共同定义标注协议。
- 用本地部署和数据不出域做差异化。
- 尽早积累中文/亚洲人群、多设备、多场景样本。

## 13. 90 天落地路线

### 第 0-2 周：原型验证

- 选定底层 baseline：OpenFace/Py-Feat/MediaPipe 至少两个。
- 跑通视频导入、逐帧特征提取、CSV 输出。
- 做一个简单时间线 UI，展示 AU/head pose/gaze。
- 选 5-10 段公开或自采样例做可视化验证。

### 第 3-6 周：可用 MVP

- 增加质量检测和不可分析提示。
- 增加短时事件候选检测。
- 支持 onset/apex/offset 人工修正。
- 支持片段导出和报告生成。
- 做 3 个真实用户访谈：心理/传播研究者、UX researcher、广告测试人员。

### 第 7-10 周：闭环测试

- 完成批量处理。
- 完成导出格式和项目文件。
- 统计人工标注节省时间。
- 建立一版模型卡和合规说明。
- 明确收费版本边界。

### 第 11-13 周：试点交付

- 找 1-2 个实验室或 UX 团队试点。
- 根据试点反馈优化标注工作流。
- 开始积累中文样本和错误案例库。
- 准备 SDK / 私有化部署方案。

## 14. 一句话战略

FaceCat 的机会不是“做一个会看穿人心的微表情 AI”，而是：

> 把面部视频变成可解释、可复核、可导出、可合规使用的行为数据。

这是一个更小、更可信、也更容易商业化的切口。

## 15. 方案复盘与优化版判断

### 15.1 这是不是最好的方案

它不是所有可能路径里收入天花板最高的方案，但它是当前信息下**风险收益比最好的第一阶段方案**。

原因是：

- 技术上可拆解：可以先用成熟开源/端侧模型完成特征提取，再把核心精力放在时间线、标注、导出、报告和可复核证据链上。
- 合规上更稳：输出面部行为数据和候选事件，避开“读心”“测谎”“员工/学生情绪评分”等高风险叙事。
- 商业上有真实痛点：研究者和 UX/广告测试人员确实需要减少人工看视频、切片、标注和写报告的时间。
- 差异化足够明确：相对开源工具，它更易用；相对商业平台，它更轻、更便宜、更本地化、更适合中文和私有化。

但它也不是一个会快速爆发的 C 端产品。它更像一个专业工具或垂直 B2B/科研工具，增长会更依赖试点、口碑、论文/案例、实验室和企业研究团队渠道。

### 15.2 原方案需要收窄的地方

原方案中“工作台 + SDK + 广告/UX + 数据集服务”方向都合理，但第一阶段同时推进会分散。建议把路线改成：

1. 第一阶段只做 **AI 辅助 FACS/AU 视频标注工作台**。
2. 第二阶段再做 **批量处理、报告模板、研究团队协作**。
3. 第三阶段根据客户来源选择 **SDK** 或 **广告/UX 反应分析**。
4. 数据集与评测服务只作为长期壁垒，不作为 MVP 主线。

最重要的措辞也要收窄：第一版不要主打“微表情识别软件”，而是主打：

> 面向研究与用户测试的视频面部行为标注工具。

“微表情”可以作为功能点出现，但不要作为唯一卖点。因为微表情识别的科学争议和技术不确定性太高，而“视频标注提效”更容易被用户理解、验证和购买。

### 15.3 优化后的 MVP

MVP 应该砍掉复杂 SDK、多人协作、多模态同步、情绪评分和模型训练，保留一个能闭环的专业工具：

- 导入视频。
- 自动做人脸质量检测。
- 提取关键点、头姿、基础 AU/blendshape 时间序列。
- 在时间线上标出“疑似短时变化片段”。
- 用户逐帧复核并调整 onset/apex/offset。
- 用户给片段打 AU 或自定义标签。
- 导出 CSV/JSON 和一份可读的分析报告。

第一版的核心成功标准不是“识别情绪有多准”，而是：

- 能否把研究者看视频和切片的时间减少 30%-50%。
- 能否让用户信任每个候选片段来自哪几帧、哪些 AU/landmark 变化。
- 能否在低质量视频上明确提示“不适合分析”，避免错误自信。
- 能否导出用户已有工作流能吃进去的数据格式。

### 15.4 可实操性评估

| 模块 | 可实操性 | 判断 |
|---|---|---|
| 视频导入、播放、逐帧预览 | 高 | 常规工程能力即可完成 |
| 人脸检测、关键点、头姿 | 高 | MediaPipe/OpenFace 等可直接作为 baseline |
| AU 或 blendshape 时间线 | 中高 | baseline 可用，但要做质量校准和展示 |
| 疑似短时事件候选 | 中 | 可以先用规则/变化点检测做可解释版本，不必一开始训练深度模型 |
| onset/apex/offset 人工校正 | 高 | 主要是交互设计和数据结构 |
| 情绪识别/微表情类别自动判断 | 低到中 | 不建议作为 MVP 承诺 |
| 商业私有化 SDK | 中 | 有价值，但要等工作台验证需求后再产品化 |
| 通用测谎/真实情绪识别 | 低 | 科学、合规和商业风险都高 |

结论：**可实操，但必须把目标从“自动判断情绪”改成“辅助发现、标注和复核面部行为事件”。**

### 15.5 推荐的 6 周验证计划

第 1 周：做命令行 baseline  
输入视频，输出每帧 face quality、landmarks/head pose、AU/blendshape CSV。

第 2 周：做最小时间线 UI  
能播放视频，显示曲线，点击曲线跳到对应帧。

第 3 周：做候选事件检测  
先用规则和变化点检测，输出候选片段，不追求完美分类。

第 4 周：做人工标注闭环  
支持调整 onset/apex/offset、打标签、保存项目。

第 5 周：做导出和报告  
导出 CSV/JSON、片段截图、候选事件表、质量说明。

第 6 周：找 3-5 个真实用户试用  
重点观察他们是否愿意用它替代部分人工标注流程，以及愿不愿意付费或参与试点。

### 15.6 Go / No-Go 标准

继续投入的条件：

- 至少 3 个目标用户认为它能明显节省标注/复核时间。
- 至少 1 个用户愿意提供真实视频做试点。
- 候选事件召回足够高，用户愿意接受一定误报。
- 导出的数据能接入用户现有论文、报告或 UX 分析流程。

暂停或换方向的信号：

- 用户只想要“自动判断情绪/测谎”，但不愿意做人工复核。
- 用户不愿上传或本地导入任何真实视频，导致无法建立样例。
- 候选事件误报多到用户觉得比手工看更累。
- 目标用户预算太低，且没有团队/机构付费路径。

### 15.7 最终优化建议

FaceCat 第一版应定位为：

> 本地运行的 AI 辅助面部行为视频标注工具，面向研究者和用户测试团队，帮助他们快速发现、复核、标注和导出面部行为事件。

第一版不要卖“微表情识别准确率”，而要卖“标注效率、证据链、隐私和导出兼容”。等工作台拿到真实用户和数据后，再决定是否扩成 SDK、广告/UX 分析平台或数据评测服务。
