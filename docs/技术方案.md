# 微表情线索标注工具技术方案

> 当前版本：2026-05-23

## 1. 定位

FaceCat 是本地优先的 AI 辅助面部行为视频标注工具。它面向研究、用户测试、广告素材评估和行为分析场景，把视频转成可复核的 AU、头姿、生理、语音和语言时间线。

FaceCat 的输出是证据和候选事件，不是自动化判断：

- 输出可观察行为：AU、landmarks、head pose、rPPG、F0、文本线索。
- 输出候选片段：onset、apex、offset、触发特征、质量上下文。
- 人工确认后再形成标注结论。
- 报告必须声明限制，不代表真实情绪、意图或是否说谎。

## 2. 理论基础

### FACS / AU 优先

FaceCat 以 FACS Action Units 为第一层语义。AU 是可观察面部肌肉动作，比“快乐、愤怒、悲伤”等情绪标签更适合和视频帧证据对应。

产品规则：

- 每个 AU 有帧级强度。
- 每个候选事件能回放到原视频帧。
- 情绪只能作为弱推断或用户自定义解释层。
- 自动候选和人工确认必须分离保存。

### 短时事件结构

微表情或短时面部变化按时间分为：

- onset：动作开始。
- apex：动作峰值。
- offset：动作回落。

第一版重点做 spotting，即找到疑似短时变化位置并帮助用户修正边界。Recognition，即给变化自动命名或解释，后置。

### 信号处理视角

FaceCat 把面部行为分析视为多条时间序列的变化检测：

- AU / blendshape 曲线。
- landmark 位移。
- head pose yaw/pitch/roll。
- rPPG 心率和呼吸率。
- 音频 F0/RMS/语速。
- 文本疏离化指标。

第一版优先使用可解释方法：滑动窗口、平滑、局部 baseline、z-score、峰值检测、持续时间约束和质量门控。

## 3. 当前四轨架构

```text
输入视频或摄像头
  |
  +-- 轨1 面部: MediaPipe -> landmarks/blendshapes/head pose -> AU
  |
  +-- 轨2 生理: forehead ROI -> CHROM/POS rPPG -> HR/BR
  |
  +-- 轨3 语音: librosa/parselmouth -> F0/RMS/语速/jitter/shimmer
  |
  +-- 轨4 语言: Whisper -> segments -> 疏离化检测
  |
  +-- 情绪弱推断: AU + HR/BR -> valence/arousal
  |
  +-- 不一致性线索: rolling window -> 9 个统计指标
  |
  +-- SnapshotBuilder -> JSON/CSV 导出
```

## 5. 数据模型

所有输出需要能回答四个问题：

1. 来自哪个视频。
2. 用哪个模型、参数和版本生成。
3. 是自动生成还是人工确认。
4. 质量和置信度如何。

核心实体：

| 实体 | 说明 |
|---|---|
| Project | 一个研究或用户测试项目 |
| VideoAsset | 原始视频资产或引用路径 |
| AnalysisRun | 一次分析运行，记录模型版本、参数、输入哈希 |
| FaceTrack | 一个被跟踪的人脸轨迹，MVP 可限制单脸 |
| FrameObservation | 单帧检测结果 |
| FeatureSeries | AU、landmark、head pose 等时间序列 |
| QualityFrame | 帧级和片段级质量信息 |
| EventCandidate | 系统生成的候选短时事件 |
| Annotation | 用户确认或修改后的标注 |
| ExportJob | 导出任务 |

## 6. 项目文件格式

第一版采用项目文件夹，后续可压缩成 `.facecatproj`：

```text
project.facecat/
  manifest.json
  assets/
    original.mp4
  runs/
    run_20260523_001/
      run.json
      features.csv
      events.json
      quality.json
  annotations/
    annotations.json
  exports/
    snapshots.json
    events.csv
    report.html
```

约束：

- `runs/` 是不可变分析结果。
- `annotations/` 是人工标注，不覆盖自动结果。
- `exports/` 是可再生成产物。
- 原始视频可以复制进项目，也可以只保存引用路径。

## 7. 质量门控

质量门控是下一阶段优先级最高的工程任务。建议输出以下指标：

- face detected confidence。
- face box size ratio。
- blur score。
- brightness / contrast。
- landmark availability。
- head pose extreme angle。
- frame drop / unstable fps。
- occlusion proxy。

产品规则：

- 低质量片段在时间线上高亮。
- 质量不过关时不输出高置信候选。
- 导出和报告必须包含质量说明。

## 8. 候选事件检测

第一版候选 detector 使用规则 ensemble：

1. 对 AU/blendshape 曲线做平滑。
2. 对每个人脸轨迹计算局部 baseline。
3. 检测短时间显著上升和回落。
4. 用最小和最大持续时间过滤。
5. 用头姿、模糊、遮挡过滤伪变化。
6. 合并相近候选。
7. 生成候选理由，例如 `AU12_peak + stable_head_pose`。

事件数据：

```json
{
  "event_id": "evt_001",
  "track_id": "face_1",
  "onset_ms": 12340,
  "apex_ms": 12480,
  "offset_ms": 12620,
  "confidence": 0.72,
  "source": "rule_change_point_v1",
  "trigger_features": ["AU12", "AU6", "mouthSmileLeft"],
  "quality_flags": ["stable_head_pose"],
  "status": "candidate"
}
```

- JSON：完整 snapshots、events、annotations、quality。
- CSV：帧级特征和事件表。
- HTML 报告：方法、参数、模型版本、质量限制、候选事件、人工确认。

## 10. 技术栈

当前实现：

| 层 | 选型 |
|---|---|
| 面部分析 | MediaPipe Face Landmarker |
| AU 映射 | blendshape -> FACS AU 查表 |
| rPPG | CHROM/POS + SciPy FFT/filter |
| 语音 | librosa + parselmouth |
| 转录 | Whisper |
| UI | PySide6 + pyqtgraph |
| 存储 | JSON/CSV snapshot |
| 测试 | pytest |

后续如拆本地服务：

- FastAPI + WebSocket 管理分析任务。
- SQLite 存项目元数据。
- Parquet/Arrow 存长视频帧级时间序列。
- Electron 或 Tauri 只作为交付壳，不影响核心引擎。

## 11. 合规与隐私

默认策略：

- 本地分析，原始视频不上传。
- 不做人脸身份识别或身份库比对。
- 支持只导出匿名化时间序列和事件。
- 删除项目时清理缩略图、缓存、临时帧。
- 日志不记录人脸图像，不记录敏感路径细节。

明确不优先支持：

- 招聘/绩效中的情绪评分。
- 学生课堂情绪或注意力打分。
- 微表情测谎和审讯结论生成。
- 犯罪倾向或心理状态自动判断。
- 未告知或无同意的隐蔽分析。

## 12. 评估指标

算法指标：

- 候选事件 recall / precision。
- 每分钟候选数量。
- onset/apex/offset 时间误差。
- AU presence F1 和 intensity 稳定性。
- 低质量片段拦截率。

产品指标：

- 人工标注时间减少比例。
- 标注者一致性提升。
- 单小时视频处理时间。
- 导出格式可用率。
- 用户是否愿意用真实视频试点。
